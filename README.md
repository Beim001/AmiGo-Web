# AmiGO Lite · 阿米诺斯文明人生模拟器

当前版本：**dev-beta-2209**（定义在 `src/version.ts`，显示在个人中心「关于我们」与致谢名单末尾）

> 以阿米诺斯维基世界观（19 世纪架空工业国家卡罗尼亚帝国）为背景的人生模拟 Web 游戏。前端使用 **React 19 + TypeScript + Vite + Tailwind CSS v4**；后端使用 **Cloudflare Workers + D1** 自建账号与云存档，面向中国大陆玩家，不依赖 Firebase / Google 服务；支持 **Bilibili Toy SDK** 登录与排行榜。

- [undefined.md](undefined.md)：玩法与数值的待定问题及决定记录（文中「第 N 题」均指此文档）。
- `wiki-contributors.md`、`list.md`：阿米诺斯维基编辑者统计与致谢名单草稿，只保存在本地，不提交到仓库。

## 一、技术栈与本地运行

- **前端**：React 19、TypeScript 5.8、Vite 6、Tailwind CSS v4（`@tailwindcss/vite`）、`motion`
- **图标与图表**：`lucide-react`（界面图标）、`simple-icons`（社区品牌图标）、`recharts`（资产全景图表）
- **字体**：`@fontsource` 自托管（Google Fonts 在中国大陆无法访问）
- **后端**：Cloudflare Workers（`worker/`，Hono 路由）+ D1 数据库；邮箱密码登录、验证邮件与找回密码（Resend 发信）、云存档、全成就名次
- **平台扩展**：Bilibili Toy SDK（`//s1.hdslb.com/bfs/seed/toy/app/sdk/toy-sdk.js`），不在 B 站环境时使用本地兜底

```bash
npm install
cp .dev.vars.example .dev.vars   # 后端本地环境变量（开发模式下邮件链接只打印到控制台）
npm run db:migrate:local         # 首次运行及新增迁移后：在本地 D1 数据库建表
npm run build                    # 后端托管 dist/，首次启动前需构建一次
npm run worker:dev               # 终端 1：启动后端（端口 8787）
npm run dev                      # 终端 2：启动前端（端口 3000，/api 自动转发到 8787）
npm run lint                     # 类型检查（前端 + 后端）
npm test                         # 单元测试：前端规则库（happy-dom）+ Worker 接口（workerd + 内存 D1）
```

- 不想启动后端时，可在 `.env.local` 设置 `VITE_SKIP_AUTH=true` 跳过登录（仅开发模式生效）。
- `npm run dev` 下右下角有紫色扳手按钮，即开发测试工具（见第五节「已完成 · 开发与测试」），生产构建中不包含。
- 部署步骤见下方「上线清单」与 `wrangler.toml` 顶部注释。

### 上线清单

每次部署前逐项核对。首次部署做全部项，之后的版本更新至少做第 2、6、7、8、9 项。

1. **Cloudflare 准备（仅首次）**：`npx wrangler login`；`npx wrangler d1 create amigo-web`，把输出的 `database_id` 填进 `wrangler.toml`，替换其中的全零占位 ID。
2. **数据库迁移**：执行 `npm run db:migrate:remote`，把 `worker/migrations/` 中尚未应用的迁移写入线上 D1。本次新增了 `0004_season_moderation.sql`（赛季作弊标记、管理员隐藏与举报）；不迁移的话，赛季上报、排行与致谢名单接口都会因缺少字段报错。
3. **域名（仅首次）**：在 Cloudflare 后台为 Worker 绑定自有域名（`*.workers.dev` 在中国大陆无法访问），并把 `wrangler.toml` 中的 `APP_URL` 填成该地址，邮件里的链接会用到它。
4. **发信（仅首次）**：`npx wrangler secret put RESEND_API_KEY`（密钥不要写进仓库），并填写 `wrangler.toml` 中的 `MAIL_FROM`。两者缺一则不会真正发信，玩家无法验证邮箱，也就无法云存档、上赛季排行。
5. **赛季排行管理员**：在 `wrangler.toml` 的 `ADMIN_EMAILS` 中填写管理员邮箱（逗号分隔）。这些账号需已注册并验证邮箱，登录后可在个人中心排行榜中处理举报、隐藏或恢复成绩。留空则没有人能处理举报。
6. **关闭开发模式**：确认线上没有设置 `DEV_MODE`（它只应出现在本地 `.dev.vars` 中），否则接口响应会直接返回邮箱验证与重置密码链接，任何人都能冒用他人邮箱注册或重置密码。
7. **版本号与测试兑换码**：核对 `src/version.ts` 的 `APP_VERSION`。以 `dev-beta` / `beta-dev` 开头时，测试兑换码 ZWZ666 在线上可用（成绩会被排行排除，但玩家能拿到无限金币与全部成就）；面向公众的正式版本需改为不带这两个前缀的版本号。大版本更新若要换赛季，同时在 `src/data/seasons.ts` 末尾新增赛季。
8. **构建与发布**：`npm run lint` 与 `npm test` 通过后执行 `npm run deploy`（先 `vite build` 再 `wrangler deploy`）。
9. **上线后检查**：在线上注册一个账号并完成邮箱验证；确认云存档能保存与读取；打开个人中心排行榜「本赛季」，确认能正常加载；用管理员账号登录，确认排行榜底部出现「排行管理」区域。

## 三、核心模块说明

### 1. 主应用（`src/App.tsx` 及从中拆出的界面组件）

| 组件 / 函数 | 作用 |
| :--- | :--- |
| `App()` | 根组件。游戏进度状态（出生登记、金币、健康、游戏年月、银行、家族、疾病与抗体、特质、声望、推演、拍卖会、外貌、寿命等）统一由 `hooks/useGameState.ts` 的 reducer 管理并自动存档；账号状态与各界面开关由 App 自己持有。 |
| `handleNextMonth()` | 推进一个月：读取存档中的输入，调用 `lib/monthTick.ts` 的纯函数 `advanceMonth` 完成全部月度结算，再把结果写回状态与存档。结算内容：俸禄或零花、月薪、童工薪水、房租、存贷利息、股市、健康与疾病、家族（生育、情人、好感衰减与分家、监护、声望、阶层提升）、推演事件、拍卖会、人生日志；健康归零时进入传承流程。 |
| `handleRegisterBirth()` | 出生登记：随机家族阶层与出身（起始资产、父母家、家人），名字中的姓换成家族姓，初始年龄 8 岁。 |
| `handleSuccession()`（`hooks/useSuccession.ts`） | 角色去世后由继承人接续（未成年继承人进入监护），可选择把前任的大事写入家族大事记。 |
| `handleResetLife()` / `handleLogout()` | 重置人生（保留账号级数据与成就）；退出登录（邮箱账号先同步云端再清除本地存档）。 |
| `ProfileModal`（`components/ProfileModal.tsx`，各标签页见 `components/profile/`） | 个人中心：名片资料、帝国排行榜、成就（含致谢名单重播）、系统设置、礼包兑换、关于我们；改名敏感词校验与冻结、慈善捐款。 |
| `ShopModal` / `ChestAnimation`（`components/ShopModal.tsx`） | 服饰商城与宝箱抽奖（保底规则见 `gacha.ts`）、理发店。 |
| `BankModal`（`components/BankModal.tsx`） | 多银行开户、存取款、贷款借还与流水。 |

### 2. 游戏规则库（`src/lib/`、`src/data/`）

| 文件 | 作用 |
| :--- | :--- |
| `monthTick.ts` | 每月结算纯函数 `advanceMonth`：输入本月状态快照，返回新状态与副作用清单（日志、成就、存档写回）；随机数全部来自参数，便于测试。 |
| `monthly.ts` | 按年龄的健康衰减、月薪（日薪 × 22，16 岁起）、未成年住父母家、老年住房加成打折。 |
| `bank.ts` / `stockMarket.ts` | 存贷利率（随历史大事件变化）与月度利息；每月推进 20 个交易日。 |
| `disease.ts` | 四个年龄段的疾病，每月按阶层倍数概率患病，部分可自愈。 |
| `lineage.ts` | 七个家族阶层（乞丐至皇族）、出身生成、童工岗位、阶层提升门槛（`PROMOTIONS`）。 |
| `family.ts` | 家族成员、结婚离婚、生育与双胞胎、情人与私生子女、好感衰减与分家、子嗣取名、继承人列表与传承、传家宝归属。 |
| `familyRank.ts` | 家族资产净值（含房产、股票、托管资金、传家宝估价）与家族排行（凝聚力 30%、财力 40%、影响力 30%）。 |
| `guardianship.ts` | 未成年继承人的财产托管、成年返还与赡养。 |
| `names.ts` / `traits.ts` / `reputation.ts` | 随机人名；特质与遗传；声望等级与变化。 |
| `heirlooms.ts` | 传家宝目录、拍卖会生成与封闭式出价。 |
| `simEvents.ts` / `lifeLog.ts` | 推演事件池（日常与机遇事件）及结算；人生日志记录与分类。 |
| `achievements.ts` / `gacha.ts` / `gifts.ts` | 成就解锁与致谢名单播放状态；抽卡概率与保底；家族礼物（品质、喜好、背包）。 |
| `data/fixedFamilies.ts` | 固定家族列表：姓氏、阶层、排行属性、出现与消失年份、是否可出生。 |
| `data/credits.ts` | 致谢名单内容，修改名单时与 `list.md` 同步。 |

### 3. 账号、存档与平台（`src/lib/`、`worker/`）

| 文件 | 作用 |
| :--- | :--- |
| `authClient.ts` | 调用 `/api/auth/*`（Cookie 会话），登记全成就名次，上报与读取赛季排行、举报与管理，把错误代码翻译为中文提示。 |
| `cloudSave.ts` | 已验证邮箱账号的云存档：登录后首次同步、两边不一致时让玩家选择、每 30 秒及推进月份后自动上传。 |
| `worker/src/index.ts` | 接口：注册、登录、退出、当前用户、重发验证邮件、邮箱验证、找回与重置密码、存档读写（版本号防覆盖）、全成就名次；按 IP 与邮箱限流。 |
| `bilibiliToy.ts` | 检测 B 站 SDK、获取 B 站资料、榜单读取与上报，不可用时返回兜底数据。 |
| `utils/sensitiveWords.ts` | 昵称长度与字符校验、分类敏感词匹配（英文词整词匹配）。 |

## 四、游戏流程

```text
[1. 登录]
  App 加载 -> /api/auth/me 检测登录（网络失败时使用本地缓存的用户，可离线游玩）
    ├─ 未登录 ──> AuthScreen（邮箱 / B 站）
    ├─ 邮箱未验证 ──> EmailVerificationScreen
    └─ 已登录 ──> 游戏主界面（顶部栏 + 角色 / 功能 / 推演 / 日志 / 家族）

[2. 一生]
  出生登记（8 岁，随机家族阶层与出身）
    └─ 每次「下个月」：收支与利息 -> 健康与疾病 -> 家族事务 -> 推演事件 / 拍卖会 -> 日志与成就
         ├─ 18 岁前住在父母家（父母无家则可能做童工），16 岁起可工作
         ├─ 成年后可结婚、生育；贵族可结识情人；家族资产与声望达标后阶层提升
         └─ 健康归零 -> 选择继承人（子嗣或兄弟姐妹）继续，或重开人生

[3. 功能中心]
  财务：银行、交易所（需家族有金融背景）、住房、资产全景
  生活：就业、医疗、商城抽卡、结婚登记
  政务与出行：性别变更、护照签证与旅行、移民居留

[4. 个人中心]
  改名（敏感词校验，违规累计 3 次冻结 90 天）、排行榜、成就与致谢名单、
  慈善捐款、保存进度、礼包兑换、关于我们、重置人生、账号管理
```
